## 3. 系统设计与整体方案

### 3.1 需求分析
- **主要难点**：
  1. 多目标跟踪中的 ID 漂移 → 虚假重复计数
  2. 推理跳帧增加轨迹关联歧义 
  3. 摄像机运动导致坐标系变换
  4. 类别分类不稳定（实例边界模糊）

### 3.2 解决方案框架
采用 **3+1 融合策略**：
- **Layer 1**: YOLO 实例分割（逐帧检测）
- **Layer 2**: ByteTrack（轨迹关联）
- **Layer 3**: 三级去重引擎（虚假计数滤波）
- **Bonus**: 光流运动补偿（摄像机自运动消除）

### 3.3 工作流程（6 步）
```
①检测     ②追踪     ③本地去重  ④地图去重  ⑤分裂处理  ⑥统计计数
(YOLO) → (ByteTrack) → (IoU)   → (光流)   → (启发式)  → (投票)
```

## 4. 核心算法与技术创新

### 4.1 多层次去重机制（重点）

**Level 1: 局部去重（空间匹配）**
```
检测到新轨迹 T_new 时，计算与历史已计数集合 C_counted 的空间相似度：
  - 条件 1: BBox IoU > recount_iou (默认 0.15)
  - 条件 2: 或中心点像素距离 < center_ratio * frame_scale
  - 限制：排除时效过长的历史记录 (max_stale_frames)
  - 若命中以上任条件，判定 T_new 为重复计数，重新链接到原有 ID，阻止总量增加
```

**Level 2: 地图坐标去重（参考系对齐）**
```
参考帧机制（每 30 帧更新）:
  - 利用 Lucas-Kanade 光流 + RANSAC 估计前后帧间的仿射/透视变换矩阵
  - 将所有有效历史中心重投影至新的统一参考坐标系空间
  
新计数验证:
  - 候选新轨迹的中心点同样投影到参考系
  - 计算其与已知轨迹在参考系下的欧氏距离
  - 距离 < map_center_ratio × map_scale:
      判定为因追踪中断但物理仍为同一物体，合并为已计数
```

**Level 3: 轨迹分裂处理（异常纠正）**
```
在确定合并至已计数记录后，执行最后一道完整性检测：
  - 异常信号：一个已计数实例同时被多个当前活跃的新老追踪框关联
  - 规则检验：计算候选框与当前持有者的相对距离与相对大小
  - 判定：如果两者距离过远且各自完整，说明原跟踪发生“一对多”伪分裂关联，
      则强行切断关联，将 candidate 提升为独立新实例并计入总数
```

### 4.2 自适应推理密度

用户可通过 `--infer_stride` 控制推理频率：
```
推理跳帧 stride = 2 (每隔 1 帧推理一次，2 倍加速)
自动调整：
  1. 置信度补偿：conf' = conf + 0.03 * log2(stride)
  2. 去重中心半径缩放：dedup_radius *= sqrt(stride)
```

效果评估见消融实验 (⬇️ 详见第 6 章)

### 4.3 运动估计与坐标变换

```
光流计算 (Lucas-Kanade + corner detection):
  检测稳定特征点 → 跟踪跨帧位移 → RANSAC 过滤外点
  ↓
估计变换（仿射2×3或透视3×3）：
  H_transform = RANSAC(inliers)
  
应用坐标系统一：
  center_ref = H_transform @ center_cur
  验证投影精度（inlier_ratio > 35%）
  
Fallback 策略：
  若光流失败 → 相位相关 (FFT 加速) 
  若仍失败 → 使用前一次变换或跳过此帧
```

## 9. Q&A 备份页

### 常见提问

**Q1: 为什么需要三级去重而不是只用 ByteTrack？**  
A: ByteTrack 本身不保证去重（可能多个轨迹跟踪同一物体），特别在推理稀疏时。三级去重通过不同角度（IoU、坐标变换、轨迹完整性）递进过滤。

**Q2: 光流失败时会怎样？**  
A: 有三重 fallback：①相位相关, ②前一帧变换缓存, ③跳过该帧（使用前一参考系）。系统鲁棒性有保证。

**Q3: 能否在盲测视频上实时运行？**  
A: ≤10s 视频，单 GPU 约 10-15s，CPU 约 60-100s。可满足离线处理需求。若需实时，考虑轻量模型 + stride。

**Q4: 标注工作量多大？**  
A: 3 段视频 (3×10s)，每人标注 1-2 段，约 2-3 小时/人。建议用 CVAT 或 labelImg 加速。

**Q5: 如何判断我们的计数对不对？**  
A: 下载官方标注 (如有)，对比误差。或手工数一遍作为 GT。提交前务必人工验证至少一段完整视频。
